# Polling Station Data – JSON & DynamoDB Guide

Generated by `parse_polling_stations.py` from the Election Commission "List of Polling Stations" PDF
(one PDF per Assembly Constituency, "AC").

Example used throughout: **AC 001 – Gummidipoondi (Thiruvallur SC), Tamil Nadu** – 344 stations, 165 local bodies, 12 pincode buckets.

---

## 1. Run the pipeline

```bash
pip install pdfplumber requests
python helper/parse_polling_stations.py assets/polling_stations/pdf/AC001.pdf \
    --out AC001 --state-code TN --state-name "Tamil Nadu" \
    --json-out assets/polling_stations/json/
```

| Step | File (inside `--out`) | Purpose |
|---|---|---|
| 1 | `01_raw_pages.json` | Table rows + text per PDF page |
| 2 | `02_stations_raw.json` | One record per station (raw cell text) |
| 3 | `03_parsed.json` | Regex-parsed building and polling areas |
| 4 | `04_normalized.json`, `04_alias_suggestions.json` | Overrides/aliases applied, filter keys derived |
| 5 | `05_validated.json`, `05_review_queue.csv/json`, `05_override_templates.json` | Validation and manual-review queue |
| 6 | `06_gemini_results.json` | Optional (`--gemini`) second opinion on flagged stations |
| 7 | `07_final_stations.json` | Final stations incl. review status |
| 8 | `08_dynamodb_items.json` / `.ndjson` | **Items to load into DynamoDB** |
| 9 | `AC001.json` | **Single JSON per constituency (for frontend / S3)** |

Re-run only the tail after manual fixes: `python helper/parse_polling_stations.py --out AC001 --steps 4-9`

### Which file do I use?

| Use case | File |
|---|---|

| DynamoDB table load | `08_dynamodb_items.ndjson` |
| Debugging a parse | `03_parsed.json`, `05_review_queue.csv` |

## 2. `AC001.json` – final constituency JSON

About 1 MB for 344 stations (too large for one DynamoDB item – the limit is 400 KB; use it as a file, not as a single item).

```
AC001.json
├── schema_version          "1.0"
├── meta                    constituency identity
├── summary                 validation totals
├── lookups                 ready-made filter data (dropdowns, reverse indexes)
└── stations[]              all polling stations
```

### 2.1 `meta`

```json
{
  "state_code": "TN", "state_name": "Tamil Nadu",
  "ac_no": 1, "ac_name": "Gummidipoondi",
  "pc_no": 1, "pc_name": "Thiruvallur", "pc_category": "SC",
  "source_file": "AC001.pdf", "total_stations": 344
}
```

### 2.2 `summary`

```json
{ "total_stations": 344, "ok": 315, "gemini_checked": 0, "approved": 0,
  "needs_review": 29,
  "open_reasons_by_severity": {"warn": 29, "error": 3},
  "global_issues": [] }
```

`global_issues` is empty when station numbers run 1..N with no gaps or duplicates and the page count matches the PDF footer.

### 2.3 `lookups`

| Key | Shape | Use |
|---|---|---|
| `pincodes` | `{ "601202": [16,17,18,19,20], ... }` | Pincode dropdown and filter. Stations with no pincode are under `"UNKNOWN"`. |
| `building_categories` | `["ANGANWADI","HIGH_SCHOOL",...]` | Building-type filter |
| `local_bodies[]` | see below | Village/panchayat dropdown |
| `wards` | `{ "<local_body_id>": { "<ward>": [ps_no,...] } }` | Ward dropdown after choosing a village |
| `localities` | `{ "<local_body_id>#<locality_id>": [ps_no,...] }` | Street/colony filter |
| `overseas_station_nos` | `[16, 36, ...]` | Stations that also serve overseas electors |

`local_bodies[]` item:

```json
{ "id": "kannampakkam", "names": ["Kannampakkam"], "types": ["P"],
  "is_revenue_village": true, "wards": ["1","2"],
  "pincodes": ["601202"], "station_nos": [16] }
```

### 2.4 `stations[]`

```json
{
  "ps_no": 16, "ps_no_suffix": null, "sl_no": 16, "page": 2,
  "station_type": "ALL VOTERS",
  "has_overseas_electors": true,
  "building": {
    "raw_text": "Panchayat Union Middle School - South Building North Facing, Kannambakkam -601202",
    "name": "Panchayat Union Middle School",
    "category": "MIDDLE_SCHOOL",
    "management": "PANCHAYAT_UNION",
    "wing_portion": "South Building North Facing",
    "facing": "NORTH",
    "room_no": null,
    "location": "Kannambakkam",
    "pincode": "601202"
  },
  "areas": [
    { "area_no": 1,
      "raw_text": "Kannampakkam(R.V)and (P), Kannapakkam (Ward - 1)",
      "local_body_name": "Kannampakkam", "local_body_type": "P",
      "is_revenue_village": true,
      "locality": "Kannapakkam", "ward_nos": ["1"],
      "door_from": null, "door_to": null,
      "local_body_canonical": "Kannampakkam",
      "local_body_id": "kannampakkam", "locality_id": "kannapakkam" }
  ],
  "filters": {
    "pincodes": ["601202"], "local_body_ids": ["kannampakkam"], "rv_ids": ["kannampakkam"],
    "ward_nos": ["1","2"], "ward_keys": ["kannampakkam#1","kannampakkam#2"],
    "locality_ids": ["kannampakkam#kannapakkam", "..."],
    "building_category": "MIDDLE_SCHOOL"
  },
  "search_text": "601202 kannambakkam kannampakkam kannapakkam ... panchayat union middle school",
  "review": { "status": "ok", "needs_review": false, "open_codes": [], "note": null }
}
```

#### Field reference

| Field | Notes |
|---|---|
| `ps_no` | Integer polling station number (unique within the AC). `ps_no_suffix` holds a letter if one is ever used (e.g. `12A`). |
| `station_type` | e.g. `ALL VOTERS` |
| `has_overseas_electors` | True when the PDF lists `[999] OVERSEAS ELECTORS` |
| `building.category` | `ANGANWADI, COMMUNITY_HALL, PANCHAYAT_SERVICE_CENTRE, HIGHER_SECONDARY_SCHOOL, HIGH_SCHOOL, MIDDLE_SCHOOL, PRIMARY_SCHOOL, MATRIC_SCHOOL, WELFARE_SCHOOL, OTHER_SCHOOL, OTHER` |
| `building.management` | `PANCHAYAT_UNION, PANCHAYAT, ADI_DRAVIDAR_WELFARE, GOVERNMENT, CSI, PRIVATE_OR_AIDED, OTHER` |
| `building.facing` | `NORTH, SOUTH, EAST, WEST` or a combination such as `NORTH_WEST`; null if not stated |
| `building.pincode` | 6 digits, or null when the PDF doesn't give one |
| `areas[].local_body_type` | `P` panchayat, `SPL_P` special-grade panchayat, `TP` town panchayat, or null |
| `areas[].is_revenue_village` | True when the PDF marks `(R.V)` |
| `areas[].ward_nos` | Array of strings; one area can span several wards (`"Ward 1 & 2"` → `["1","2"]`) |
| `areas[].door_from/door_to` | Set when a street is split across stations by door number (`Door No From 1 to 500`); `door_to` is null for "From 501" |
| `local_body_id` | Lower-case slug of the (alias-corrected) village name; the key used for all filtering |
| `filters.*` | Pre-computed de-duplicated filter keys for the station |
| `search_text` | Lower-case words for simple client-side text search |
| `review.status` | `ok`, `needs_review`, `approved` (you checked it), `gemini_checked` |
| `review.open_codes` | Unresolved issues, e.g. `no_pincode`, `ward_typo_autofixed`, `placeholder_text` |

> **Keep `raw_text`.** It is the original PDF text. If a parsing rule changes later you can re-derive without re-reading the PDF, and your UI can show the source on a "view original" link.

## 3. DynamoDB design

One table for every constituency. Each constituency lives under its own partition key (`AC#<state>#<ac_no>`).

### 3.1 Table

| Setting | Value |
|---|---|
| Table name | `ElectionPollingStations` (your choice) |
| Partition key | `PK` (String) |
| Sort key | `SK` (String) |
| Billing | On-demand (traffic is read-heavy and spiky) |
| GSI `GSI1` | Partition key `GSI1PK` (String), sort key `GSI1SK` (String), projection `ALL` |

Create it:

```bash
aws dynamodb create-table \
  --table-name ElectionPollingStations \
  --billing-mode PAY_PER_REQUEST \
  --attribute-definitions AttributeName=PK,AttributeType=S AttributeName=SK,AttributeType=S \
                          AttributeName=GSI1PK,AttributeType=S AttributeName=GSI1SK,AttributeType=S \
  --key-schema AttributeName=PK,KeyType=HASH AttributeName=SK,KeyType=RANGE \
  --global-secondary-indexes '[{
      "IndexName":"GSI1",
      "KeySchema":[{"AttributeName":"GSI1PK","KeyType":"HASH"},{"AttributeName":"GSI1SK","KeyType":"RANGE"}],
      "Projection":{"ProjectionType":"ALL"}}]'
```

### 3.2 Item types

AC 001 produces **3,161 items**: 344 station + 2,639 index + 165 local body + 12 pincode + 1 meta. About 740 K items for all 234 TN constituencies – small for DynamoDB.

| Entity | PK | SK | Count (AC001) |
|---|---|---|---|
| `AC_META` | `AC#TN#001` | `META` | 1 |
| `STATION` | `AC#TN#001` | `PS#0016` | 344 |
| `LOCAL_BODY` | `AC#TN#001` | `LB#kannampakkam` | 165 |
| `PINCODE` | `AC#TN#001` | `PIN#601202` | 12 |
| `INDEX` | `AC#TN#001` | `IDX#<KIND>#<value>#PS#0016` | 2,639 |

#### `AC_META`
```json
{ "PK":"AC#TN#001","SK":"META","entity":"AC_META",
  "ac_no":1,"ac_name":"Gummidipoondi","pc_no":1,"pc_name":"Thiruvallur","pc_category":"SC",
  "state_code":"TN","state_name":"Tamil Nadu","total_stations":344,
  "pincodes":["600052","601101","..."],"local_body_count":165,
  "needs_review_count":29,"source_file":"AC001.pdf" }
```

#### `STATION` (largest item is about 9 KB)
```json
{ "PK":"AC#TN#001","SK":"PS#0016","entity":"STATION",
  "state_code":"TN","ac_no":1,"ac_name":"Gummidipoondi","pc_no":1,"pc_name":"Thiruvallur","pc_category":"SC",
  "ps_no":16,"ps_no_suffix":null,"sl_no":16,"station_type":"ALL VOTERS","has_overseas_electors":true,
  "source":{"file":"AC001.pdf","page":2},
  "building":{ "...same as JSON..." }, "areas":[ "...same as JSON..." ],
  "filters":{ "...same as JSON..." }, "search_text":"601202 kannambakkam ...",
  "needs_review":false,"review_status":"ok","review_codes":[] }
```
The `SK` zero-pads the number (`PS#0016`) so a Query returns stations in numeric order.

#### `INDEX` (one per station × filter value)
```json
{ "PK":"AC#TN#001","SK":"IDX#PIN#601201#PS#0001","entity":"INDEX","kind":"PIN","value":"601201",
  "GSI1PK":"AC#TN#001#PIN#601201","GSI1SK":"PS#0001",
  "ps_no":1,"building_name":"Panchayat Union Primary School","location":"Egumadurai",
  "pincode":"601201","category":"PRIMARY_SCHOOL","areas":6 }
```

| `kind` | `value` | Count (AC001) |
|---|---|---|
| `PIN` | pincode | 327 |
| `LB` | `local_body_id` | 386 |
| `RV` | `local_body_id` of revenue villages | 123 |
| `WARD` | `<local_body_id>#<ward>` | 509 |
| `LOC` | `<local_body_id>#<locality_id>` | 907 |
| `CAT` | building category | 344 |
| `OVERSEAS` | `Y` | 43 |

Index items carry a small summary (name, location, pincode, category), so list pages need no second read.

#### `LOCAL_BODY` and `PINCODE` (for dropdowns)
```json
{ "PK":"AC#TN#001","SK":"LB#kannampakkam","entity":"LOCAL_BODY","id":"kannampakkam",
  "names":["Kannampakkam"],"types":["P"],"is_revenue_village":true,
  "wards":["1","2"],"pincodes":["601202"],"station_nos":[16] }

{ "PK":"AC#TN#001","SK":"PIN#601202","entity":"PINCODE","pincode":"601202",
  "station_nos":[16,17,18,19,20],"count":5 }
```

### 3.3 Access patterns

| # | Question | Operation |
|---|---|---|
| 1 | AC details | `GetItem PK=AC#TN#001, SK=META` |
| 2 | All stations in the AC | `Query PK=AC#TN#001 AND begins_with(SK,"PS#")` |
| 3 | One station | `GetItem PK=AC#TN#001, SK=PS#0016` |
| 4 | Village dropdown | `Query PK=AC#TN#001 AND begins_with(SK,"LB#")` |
| 5 | Pincode dropdown | `Query PK=AC#TN#001 AND begins_with(SK,"PIN#")` |
| 6 | Stations by pincode | `Query GSI1 GSI1PK="AC#TN#001#PIN#601202"` |
| 7 | Stations by village / revenue village | `Query GSI1 GSI1PK="AC#TN#001#LB#kannampakkam"` (or `#RV#`) |
| 8 | Stations by village + ward | `Query GSI1 GSI1PK="AC#TN#001#WARD#kannampakkam#2"` |
| 9 | Stations by locality / street | `Query GSI1 GSI1PK="AC#TN#001#LOC#kannampakkam#kannapakkamcolony"` |
| 10 | Stations by building type | `Query GSI1 GSI1PK="AC#TN#001#CAT#PRIMARY_SCHOOL"` |
| 11 | Overseas-elector stations | `Query GSI1 GSI1PK="AC#TN#001#OVERSEAS#Y"` |
| 12 | Needs-review stations | `Query PK=AC#TN#001 AND begins_with(SK,"PS#")` with `FilterExpression needs_review = true` (or use the CSV) |
| 13 | Two filters at once (pincode + ward) | Run two index queries and intersect the `ps_no` values in code (each result is small), then `BatchGetItem` the stations |
| 14 | Free-text search | Filter `search_text` in the client after loading the AC, or use OpenSearch if you need it server-side |

Example (Python / boto3):

```python
import boto3
from boto3.dynamodb.conditions import Key

table = boto3.resource("dynamodb").Table("ElectionPollingStations")

def stations_by_ward(ac_pk, local_body_id, ward):
    items, kwargs = [], dict(
        IndexName="GSI1",
        KeyConditionExpression=Key("GSI1PK").eq(f"{ac_pk}#WARD#{local_body_id}#{ward}"))
    while True:
        r = table.query(**kwargs)
        items += r["Items"]
        if "LastEvaluatedKey" not in r: return items
        kwargs["ExclusiveStartKey"] = r["LastEvaluatedKey"]

hits = stations_by_ward("AC#TN#001", "kannampakkam", "2")
full = table.get_item(Key={"PK": "AC#TN#001", "SK": f"PS#{hits[0]['ps_no']:04d}"})["Item"]
```

### 3.4 Loading the data

```python
import json, boto3
from decimal import Decimal

table = boto3.resource("dynamodb").Table("ElectionPollingStations")
with open("AC001/08_dynamodb_items.ndjson", encoding="utf-8") as f, table.batch_writer() as bw:
    for line in f:
        bw.put_item(Item=json.loads(line, parse_float=Decimal))   # ints load as-is, floats need Decimal
```

Notes:
- Writing about 3,200 items per AC takes seconds. `batch_writer` retries unprocessed items automatically.
- `null` values load as DynamoDB `NULL`; empty arrays load as empty lists.
- Check item sizes if you add fields: the 400 KB item limit is far away (station items are under 10 KB).

### 3.5 Reloading a constituency

IDs are derived from names (`local_body_id`), so adding an alias can change ids and therefore index keys. Do not just re-put over the old data; stale index items would remain.

1. Query all items with `PK = AC#TN#001` and delete them (`batch_writer().delete_item(Key={PK, SK})`).
2. Load the new `08_dynamodb_items.ndjson`.

For zero-downtime reloads, put a version in the PK (`AC#TN#001#v2`) and switch the app to it after loading.

const ac = await (await fetch("/data/AC001.json")).json();

## 5. Data-quality workflow

1. Open `05_review_queue.csv` (raw PDF text next to the parsed result).
2. Correct values in `manual_overrides.json` (templates in `05_override_templates.json`), and set `"approved": true`.
3. Add spelling-variant fixes under `aliases`, using `04_alias_suggestions.json` as a guide:

```json
{
  "aliases": { "Obasamuthiram": "Obasamudram", "Athupakkam|601102": "Athupakkam (Uthukottai)" },
  "stations": {
    "29":  { "approved": true, "building": { "pincode": "601201" } },
    "216": { "approved": true, "areas": { "2": { "locality": "Lachivakkam", "ward_nos": ["2"] } } }
  }
}
```

4. Re-run `python helper/parse_polling_stations.py --out AC001 --steps 4-9`, then reload DynamoDB (section 3.5).

| Review code | Meaning | Typical action |
|---|---|---|
| `no_pincode` | The PDF text has no pincode | Add the pincode manually |
| `ward_typo_autofixed` | e.g. `(Ward 20,` read as ward 2 | Confirm, then `approved: true` |
| `placeholder_text` | The PDF itself says "zzz" | Nothing to fix; approve |
| `ward_word_without_number` | e.g. `(Ward &2)` | Set the ward by hand |

## 5.2 Importing Extracted Data into DynamoDB (`import_polling_stations.py`)

To ingest `.ndjson` streaming files or full constituency JSON bundles into DynamoDB:

By default, the script performs a **smart delta import**: it queries existing DynamoDB items for the constituency, skips complete stations, and only inserts newly discovered stations or updates stations with missing details (such as missing pincode, building subfields, polling areas, or flags).

```bash
# 1. Delta import a single NDJSON file (only inserts missing stations or updates missing fields)
python scraper/import_polling_stations.py scraper/assets/polling_stations/AC001/08_dynamodb_items.ndjson

# 2. Delta import all constituencies in a directory
python scraper/import_polling_stations.py scraper/assets/polling_stations/

# 3. Delta import with specific constituency filter (--ac or --constituency)
python scraper/import_polling_stations.py scraper/assets/polling_stations/ --ac 1

# 4. Import ONLY missing stations and missing constituencies (skips all existing stations, no detail updates)
python scraper/import_polling_stations.py scraper/assets/polling_stations/ --missing-only

# 5. Import ONLY completely missing constituencies (skips any AC that already exists in DB)
python scraper/import_polling_stations.py scraper/assets/polling_stations/ --missing-constituencies-only

# 6. Full overwrite import (--force / -f): Overwrites all records without delta filtering
python scraper/import_polling_stations.py scraper/assets/polling_stations/AC001/08_dynamodb_items.ndjson --force

# 7. Clean reload (--reload / --clean): Purges existing records for the AC first, then re-imports
python scraper/import_polling_stations.py scraper/assets/polling_stations/AC001_polling_stations.json --reload
```

Supported import flags:
- `--missing-only`, `--only-missing`, `--missing-stations-only`: Import only newly missing stations and missing constituencies. Any station already present in DynamoDB is skipped without updating existing details.
- `--missing-constituencies-only`, `--only-missing-constituencies`: Import only completely missing constituencies. Any constituency that already exists in DynamoDB is skipped immediately.
- `--force`, `-f`: Force full import of all items, overwriting existing records without delta filtering.
- `--reload`, `--clean`: Purge all existing records for the targeted constituency before importing.
- `--ac`, `--constituency <N>`: Optional AC number filter to process only matching constituencies.
- `--table-name`: Target DynamoDB table (default: `knowyourmla_polling_stations` or `POLLING_STATIONS_TABLE` env var).
- `--region`: AWS region (default: `ap-south-2` or `AWS_REGION` env var).

## 6. Known limitations

- **Spelling variants** of the same village (`Thokkamur`/`Thakkamur`) are different `local_body_id`s until you add an alias.
- **Same name, different village** (two `Athupakkam`s with different pincodes) share an id by default. Use the `"Name|pincode"` alias form to separate them.
- **Missing pincodes** in the PDF leave a station out of pincode filters (they appear under `UNKNOWN`) until you fill them.
- **Other constituencies** may have layouts this parser hasn't seen. Check `summary.global_issues` and the review queue on each new PDF.
- **Voter counts, booth coordinates and results** are not in the PDF. Add them later as separate items under the same `PK` (for example `SK = PS#0016#STATS`) so the station item stays small.
